This page covers common DNS problems and how to fix them. The examples use the `datumctl dns` plugin. To install it, see [Operations](/domain-dns/operations#before-you-begin). Add `--verbose` to any `datumctl dns` command to see the underlying cause of an error.

## My domain doesn't resolve

Work through these checks in order.

1. **Check delegation.** Run `datumctl dns zone nameservers example.com --check`. If delegation is `Incomplete` or `Partial`, set Datum's nameservers at your registrar. If it's `Unknown`, the zone is new; wait a few minutes and check again.
2. **Check for DNSSEC.** If the domain resolves with `dig +cd example.com` but returns `SERVFAIL` with `dig example.com`, a leftover `DS` record at your registrar is the cause. Datum DNS doesn't support DNSSEC yet. Remove the `DS` record at your registrar, and resolvers recover as their cached copy expires. See [DNSSEC](/domain-dns/dns#dnssec).
3. **Check the record.** Run `datumctl dns record list example.com --name www`. If the record isn't there, or isn't `Programmed`, see the sections below.
4. **Check Datum's answer.** Run `dig www.example.com @ns1.datumdomains.net`. If Datum answers correctly but your resolver doesn't, it's holding an old answer. Wait for the old record's TTL.

## A record is stuck at Pending

`Pending` is normal for a few moments after a change. If it lasts, ask Datum why:

```bash
datumctl dns record describe example.com www
```

`describe` shows the reason for each value. Use the reason to find the fix in the table below.

## A record reports Conflict or Not owner

| Status | What it means | What to do |
| --- | --- | --- |
| `Conflict` | Another record already occupies that name. | The name is usually outside the zone. Check for `www.example.com` where you meant `www`: names are relative to the zone. |
| `Not owner` | Another record set already owns that name. `describe` names it. | Change the record through the record set that owns it, or delete that record set first. |

Records that Datum manages for you, such as a zone's `SOA` and apex `NS` records and the records an [Application Load Balancer](/alb/overview) creates, change back if you edit them by hand. To see which records Datum manages, run `datumctl dns record list example.com --managed`.

## I can't create a zone for my domain

A domain can belong to only one zone on Datum. If another zone already claims the domain, the new zone isn't accepted. Check whether the zone already exists in another of your projects. If you can't find it, contact [support@datum.net](mailto:support@datum.net).

A zone's domain name can't be changed after you create it. To use a different domain, create a new zone.

## My zone has no nameservers

If `datumctl dns zone create` reports `Waiting for domain ownership verification before provisioning DNS`, the zone exists, but Datum won't serve it until you prove you own the domain. Until then, the zone has no nameservers and its records stay `Rejected`. You don't need to recreate the zone. [Verify the domain](/domain-dns/domains#verify-a-domain), and Datum provisions the zone and its records.

## DNS isn't enabled for my project

If a command fails with exit code `3` (`DNS_FORBIDDEN`), either your account isn't allowed to manage DNS in the project, or DNS isn't enabled for it. To enable DNS, run the following command:

```bash
datumctl services enable dns.networking.miloapis.com --wait
```

If DNS is already enabled, ask your project's administrator for access.

## No project is set

The `dns` plugin never guesses a project. Run `datumctl ctx use your-org-id/your-project-id`, or add `--project your-project-id` to the command.

## Import skipped some records

When you import a zone, the importer skips `DS`, `DNSKEY`, `RRSIG`, `NSEC`, and `NSEC3` records and lists them in a warning. That's expected, because Datum DNS doesn't support DNSSEC yet. Before you move your domain to Datum, turn off DNSSEC at your registrar. See [DNSSEC](/domain-dns/dns#dnssec).

## A record that points at a load balancer doesn't work

See [Point a domain at a load balancer](/domain-dns/point-to-alb#troubleshooting).

## ExternalDNS doesn't create records

If you use [ExternalDNS](/domain-dns/operations#automate-records-with-externaldns) with the Datum webhook:

- The webhook manages only hostnames inside one of your `DNSZone` resources. Create the zone first.
- The webhook only changes records labeled with its own `--owner-id`. A record created by hand, or by another ExternalDNS instance, isn't changed. The `datum_dns_ownership_conflicts_total` metric counts these.
- The webhook needs permission to read `dnszones` and to manage `dnsrecordsets` in your project.

For the webhook's metrics, see [Observability](/domain-dns/observability#externaldns-webhook-metrics).

## Private DNS

These checks apply to [Private DNS](/domain-dns/private-dns) names, which resolve only inside a gVPC network.

### A private name doesn't resolve

Work through these checks in order, from an Instance on the network:

1. **Use the full name.** Look up `web-default-us-central-1-0.instances.datum.internal`, not `web-default-us-central-1-0`. Short names depend on search domains.
2. **Check the network.** A private name resolves only from networks its zone is associated with. An Instance name resolves only from the Instance's own network.
3. **Check the resolver.** Run `cat /etc/resolv.conf` in a `general-purpose` Instance. The app must use these resolvers. An app that uses its own resolver, such as DNS over HTTPS or a hard-coded public resolver, can't resolve private names.
4. **Check the Instance.** An Instance name exists only while the Instance is ready. Run `datumctl get instance INSTANCE_NAME -o yaml` and check `status.dns`. If its condition isn't `Ready`, the reason says why.
5. **Check the zone.** Run `datumctl get dnszone ZONE_NAME`. If `PROGRAMMED` isn't `True`, wait a minute and check again. A zone that isn't associated with any network shows no status.
6. **Check the record or association.** See the next section.
7. **Check `CNAME` targets.** A `CNAME` that points into another zone may return only the `CNAME`. Point it at a name in the same zone, or use `AAAA` records.

### A record set or association isn't accepted

Read the reason:

```bash
datumctl get dnsrecordset RECORDSET_NAME \
  -o jsonpath='{.status.conditions[?(@.type=="Accepted")].reason}'
datumctl get dnszoneassociation ASSOCIATION_NAME \
  -o jsonpath='{.status.conditions[?(@.type=="Accepted")].reason}'
```

| Reason | What it means | What to do |
| --- | --- | --- |
| `UnsupportedPrivateRecord` | The record set uses a type or name that private zones don't support, such as `ALIAS`, `SOA`, or a `CNAME` at the zone's own domain. | Use a supported record. See [Record rules](/domain-dns/private-dns-reference#record-rules). |
| `ReservedScope` | The name is at or below a name that a Datum service owns, such as `instances.datum.internal`. | Use a different name. |
| `NameConflict` | An older record set already has this name and type, or a `CNAME` shares the name with another type. | Change the record in the record set that has it, or delete that record set first. |
| `MissingSRVTargetAddress` | An `SRV` target has no `A` or `AAAA` record in the same zone. | Add an address record for the target in the zone. |
| `ConflictingTTL` | One name in the record set has two different TTLs. | Use one TTL for each name. |
| `InvalidRecord`, `InvalidTTL` | A value doesn't match its record type, or the TTL is out of range. | Fix the value. |
| `ApexConflict` | Another zone with the same domain is associated with this network. The association whose name sorts first keeps the domain. | Delete the association you don't want. |
| `InvalidReference` | The association's zone or DNS context doesn't exist, was deleted, or was replaced by a new one with the same name. | Check both names. If they exist, delete the association and create it again. |

A request can also be refused when you apply it. A message that starts with `ReservedScope:` means the same as the reason above. A `not found` error, or one that mentions `private zone lookup` or `resolver context lookup`, means the zone or DNS context you named doesn't exist in the project.

### A name returns an old answer

Clients and resolvers keep an answer until its TTL expires. Instance names have a 30 second TTL. Records you create default to 300 seconds. To make changes show up sooner, lower the record's TTL before you change it.
