title: "Private DNS"
description: "Resolve private service and resource names within a gVPC network."
---

Private DNS gives resources in a [gVPC](/galactic-vpc/overview) network names
that resolve only from that network. It provides a consistent discovery layer
for private addresses without requiring every product or workload to run its
own DNS server.

## What you can do

With Private DNS, you can:

- **Reach resources by name:** Use DNS names instead of private IP addresses
  that can change over a resource's lifetime.
- **Use automatic service names:** Integrated Datum services publish names for
  resources such as Compute Instances.
- **Create private namespaces:** Organize internal apps under private zones
  that only associated networks can resolve.
- **Reuse internal names safely:** Different networks can use the same names
  and overlapping private addresses without exposing answers to each other.
- **Keep records aligned with resources:** Service-managed records update or
  disappear as their resources and addresses change.

Apps use ordinary DNS lookups. On an associated network, private names
resolve alongside public names with no resolver configuration in the app.

## Private and public DNS

Datum offers two complementary DNS capabilities:

| Capability | Where names resolve | Typical use |
| --- | --- | --- |
| [Authoritative DNS](/domain-dns/dns) | The public internet | Websites, public APIs, email, and domain records |
| Private DNS | Inside an associated network | Private Instances, internal services, and service discovery |

Private DNS records aren't published to public DNS. A private name doesn't
make a resource reachable from the internet or grant network access to it.

## Names and zones

Every network gets a managed private zone named `datum.internal`. Datum
services publish their names in it. For example, an Instance named
`web-default-us-central-1-0` is reachable at:

```text
web-default-us-central-1-0.instances.datum.internal
```

Every network uses the same zone name, but each network has its own copy. A
lookup of that name returns the Instance on the client's network, and returns
nothing on any other network. Use the full name: short names depend on the
search domains the client is configured with.

You can also associate private zones with a network for your own names. Their
records resolve only from the networks the zone is associated with.

## What Private DNS doesn't do

- **Provide public discovery:** Private names aren't available through public
  DNS.
- **Grant network access:** Whether a client can reach the returned address
  depends on the network, not on DNS. See
  [Traffic and connecting](/galactic-vpc/networks/traffic).
- **Replace app health checks:** A name can resolve while the app itself is
  unavailable.
- **Remove cached answers immediately:** Clients can keep an older answer
  until its DNS TTL expires.
