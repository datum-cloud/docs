<Update label="November 4, 2026" description="Cloud portal" tags={["AX/DX/UX"]}>
  ## Faster pages and access fixes

  The cloud portal loads faster and handles a few edge cases more reliably.

  - **Faster first load:** dashboard and project pages render right away instead of showing a blank page while they load. Tablets no longer see the navigation collapse and shift the page.
  - **Fixed:** members with read-only access can now open the VPC pages. Create, edit, and delete controls are hidden when you don't have permission to use them.
  - **Fixed:** an organization you delete no longer appears in your organizations list.
  - **Fixed:** your first and last name can no longer be set to an email address.
</Update>

<Update label="November 3, 2026" description="Private DNS" tags={["Connect"]}>
  ## Clearer Private DNS zones in the portal

  Private DNS zones for your VPC networks are now easy to tell apart from public zones.

  - The DNS list shows **Private** in the DNS host column instead of a lookup that never finishes.
  - The zone page hides the **Nameservers** tab, since private zones don't use public nameservers.
  - Each zone's description names the VPC it serves.

  See [Private DNS](/domain-dns/private-dns).
</Update>

<Update label="November 2, 2026" description="Billing" tags={["GA"]}>
  ## Billing is available to all organization owners

  Billing in the cloud portal is now generally available. Organization owners can manage billing accounts, payment methods, and invoices.

  - **Owners only:** billing pages, menu items, and links appear only for organization owners. Other members don't see them.
  - **Discounts:** a billing account now shows any discount that applies to it, per service or across all usage. Discounts are applied to invoices automatically.
  - **Payment terms:** organizations that can't pay by card can apply to pay by invoice. Track the application's status from onboarding or **Payment methods**.
  - **One invoice email:** billing settings now have a single **Invoice email** field. Leave it empty to send invoices to the billing contact.
  - **Fixed:** past invoices no longer include old invoices that stayed open with outdated totals.

  See [Organizations](/organizations/overview).
</Update>

<Update label="October 30, 2026" description="Network Load Balancer" tags={["Deliver"]}>
  ## Network load balancers in the portal

  Publish TCP and UDP services from your VPC network to the internet, and manage them from the cloud portal under **NLB**.

  - **Create and manage:** create a network load balancer, then add, edit, or delete its listeners. Editing a listener keeps its address.
  - **Overview:** each load balancer shows its generated hostname, IPv6 address, network, and locations, plus every listener's port, backend, health, and health check.
  - **UDP ports:** [network services](/galactic-vpc/networks/network-services) now accept UDP ports. An HTTPProxy that points at a UDP port reports an unsupported-protocol reason that tells you to use an HTTP port over TCP.

  Each route forwards to one backend. TLS listeners aren't supported yet, but a TCP listener passes TLS traffic through unchanged.
</Update>

<Update label="October 29, 2026" description="datumctl" tags={["datumctl"]}>
  ## Correct version reporting for Nix installs

  `datumctl` installed from the Nix flake now reports a valid version.

  - **Fixed:** `datumctl version` no longer crashes when `datumctl` is installed with `nix profile install` or run with `nix run`.
  - **Fixed:** plugin compatibility checks and update checks now read a real version in Nix builds instead of a placeholder.

  To pick up the fix, reinstall or upgrade `datumctl` from the flake. See [Install datumctl](/datumctl/install).
</Update>

<Update label="October 26, 2026" description="Application Load Balancer" tags={["Deliver"]}>
  ## DNS status for hostnames hosted outside Datum

  If a custom hostname's DNS is hosted elsewhere, the ALB now shows whether that hostname points at your load balancer.

  - **DNS Ready** appears once Datum sees your CNAME, or matching IP addresses, pointing at the ALB.
  - **Awaiting DNS** appears until then. The tooltip names the record to add.
  - **Fixed:** a wildcard hostname that your project isn't entitled to now reports `ListenersNotValid` instead of staying `Pending` indefinitely.

  See [Point a domain to your ALB](/domain-dns/point-to-alb) and [Wildcard hostnames](/alb/configuration/wildcard-hostnames).
</Update>

<Update label="October 21, 2026" description="Application Load Balancer" tags={["Build", "Connect"]}>
  ## Run gRPC APIs on Datum

  The Application Load Balancer now supports HTTP/2 from clients to origins, so gRPC APIs can run on Datum and be called at their ALB hostname.

  - **Compute:** add `--http2` at deploy time to prepare the workload's ALB for gRPC clients. The setting persists across later deploys. Requires the compute plugin v0.12.11 or later.
  - **Network services:** mark a service port as HTTP/2 so any ALB using that port can serve gRPC. Requires the network and alb plugins v0.32.26 or later.
  - **Hostnames:** generated and custom hostnames both support HTTP/2. HTTP/1.1 clients are unaffected.
  - **TLS:** the ALB terminates TLS, so your server speaks plain gRPC.

  Origins added by URL, including servers outside Datum, still use HTTP/1.1. If your app uses WebSockets, serve them on a separate port without HTTP/2.

  [Read the announcement](https://github.com/orgs/datum-cloud/discussions/310)
</Update>

<Update label="October 13, 2026" description="datumctl" tags={["datumctl", "Patch"]}>
  ## New datumctl plugins and assistant capabilities

  Install plugins from the official catalog with `datumctl plugin install <name>`.

  - **compute:** deploy, scale, restart, and roll out workloads, stream `logs`, run `exec` inside an instance, publish images with `build`, and check remaining project `quota`.
  - **alb:** create a load balancer with an immediate hostname, add custom domains with verification tracking, route paths and split traffic by weight, and manage WAF, basic auth, headers, and request logs.
  - **network:** create private IPv6 networks, see where they run, give workloads stable service names and named ports, and manage instance interfaces. Deletions list affected resources and ask for confirmation.

  Patch, the Datum assistant, can now diagnose why a network or network service isn't working or receiving traffic, and can create networks and network services. It shows exactly what it will change and waits for your approval. Use it in the [cloud portal](https://cloud.datum.net) or with `datumctl plugin install assistant`.

  [Read the announcement](https://github.com/orgs/datum-cloud/discussions/306)
</Update>

<Update label="October 13, 2026" description="datumctl v0.22.0" tags={["datumctl"]}>
  ## Upgrade every plugin in one command

  - `datumctl plugin upgrade --all` upgrades every installed plugin that has a newer release and skips the rest.
  - Each plugin is fetched from the catalog or GitHub repository it was installed from, with the same checksum and compatibility checks as a fresh install.
  - If one plugin fails, the others still upgrade and the failures are listed at the end.
  - Fixed upgrading a third-party catalog plugin by name, which previously looked only in the official catalog.

  [Read the announcement](https://github.com/orgs/datum-cloud/discussions/304)
</Update>

<Update label="October 7, 2026" description="Application Load Balancer" tags={["Deliver", "Early access"]}>
  ## Wildcard hostnames

  An Application Load Balancer can now serve every subdomain of a domain you own. Add a hostname such as `*.example.com` and get one automatically issued and renewed certificate that covers all names one level below the domain.

  ```bash
  datumctl alb hostname add my-app '*.example.com'
  datumctl alb describe my-app
  ```

  Publish the `_acme-challenge` CNAME record that `describe` shows. The certificate is typically issued within a few minutes, and the record stays the same at renewal.

  This is an early-access capability that isn't turned on by default, so contact Datum to enable it for your project. It requires the alb plugin v0.32.3 or later (`datumctl plugin upgrade alb`). A wildcard matches one label level only: `*.example.com` covers `app.example.com` but not `a.b.example.com`.

  [Read the announcement](https://github.com/orgs/datum-cloud/discussions/303)
</Update>

<Update label="September 29, 2026" description="Patch" tags={["AX/DX/UX"]}>
  ## Patch can work with your compute, DNS, and load balancing

  Patch can now query Compute, DNS, and Application Load Balancer data directly, so troubleshooting follows the actual cause instead of inferring it from generic resource reads.

  - **Compute:** follows top-level reasons such as `Available=False` with `QuotaNotGranted` down to the instance-level condition that holds the cause.
  - **DNS:** diagnoses zones, records, and delegation, including domain verification, conflicting records, and zone imports.
  - **Load balancing:** covers certificates, unreachable backends, edge propagation, and access logs.

  The service tools are read-only. Any change goes through a plan you review and approve. Which tools are available depends on what each project is entitled to.

  In the terminal, run `datumctl assistant` for a full-screen chat, `datumctl assistant chat "..."` for a one-shot answer in scripts, or `datumctl assistant resume` to search project conversations. Install it with `datumctl plugin install assistant`.

  [Read the announcement](https://github.com/orgs/datum-cloud/discussions/300)
</Update>
