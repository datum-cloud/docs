## Create a Secret with datumctl

A Secret is a Kubernetes-style resource, so you create it with a manifest and `datumctl apply`. To create a Secret, follow these steps:

1. Save the following manifest as `api-secrets.yaml`:

   ```yaml
   apiVersion: v1
   kind: Secret
   metadata:
     name: api-secrets
   type: Opaque
   stringData:
     db-password: PASSWORD
   ```

   Replace `PASSWORD` with the value to store.

2. To create the Secret in your active project, run the following command:

   ```bash
   datumctl apply -f api-secrets.yaml
   ```

To target a different project, add `--project PROJECT_ID`. For more information, see [Contexts and scoping](/datumctl/contexts-and-scoping).

<Warning>
  A manifest with `stringData` holds the secret value in plain text. Don't commit it to source control.
</Warning>

## List and inspect Secrets

To list the Secrets in your project, run the following command:

```bash
datumctl get secrets
```

To inspect one Secret, run the following command:

```bash
datumctl describe secret api-secrets
```

## Update or delete a Secret

To change a Secret, edit the manifest and run `datumctl apply -f` again. To delete it, run the following command:

```bash
datumctl delete secret api-secrets
```

## Use a Secret

Compute workloads can read a Secret as environment variables or as files. For more information, see [Configuration](/compute/configuration).
