HTTP Basic Auth protects a load balancer with a username and password. [Envoy](/platform/envoy) checks the credentials on every request, at the edge, before the request reaches your origin. Requests without valid credentials get `401 Unauthorized`, and browsers show a sign-in prompt.

There are two ways to set it up:

- **`datumctl alb auth`** is the quickest. One command sets the users, creates the Secret, and attaches the policy. Every user gets the same password.
- **A `SecurityPolicy` manifest** gives you full control: a different password for each user, the username passed to your origin, configuration kept in Git, or protection for a single path.

## Set up Basic Auth with datumctl alb

To protect a load balancer, pass one or more users, and give their password on standard input:

<Tabs>
  <Tab title="macOS / Linux">

  ```bash
  read -s -p "Password: " password && echo
  printf '%s' "$password" | datumctl alb auth set ALB_NAME --user admin --password-stdin
  ```

  </Tab>
  <Tab title="Windows (PowerShell)">

  ```powershell
  $password = Read-Host "Password" -MaskInput
  $password | datumctl alb auth set ALB_NAME --user admin --password-stdin
  ```

  </Tab>
</Tabs>

To admit several users, repeat `--user`, as in `--user admin --user editor`. They all share the one password. Each `alb auth set` replaces the whole user list, so pass every user each time. To check a change without applying it, add `--dry-run`.

`alb auth set` creates a Secret named `ALB_NAME-basic-auth` and a `SecurityPolicy` named `ALB_NAME` that targets the load balancer's **Gateway**, so it covers every route.

<Warning>
  A `SecurityPolicy` that targets one of the load balancer's **routes** replaces the Gateway's policy for that route. If you add any route-level policy, even one with only CORS, Basic Auth from `alb auth set` stops applying to that route, and `datumctl alb describe` still shows it as enabled. To combine Basic Auth with anything else, use a [manifest](#set-up-basic-auth-with-a-securitypolicy) and put every setting in one route-level policy.
</Warning>

To see which usernames are allowed, run the following command:

```bash
datumctl alb auth list ALB_NAME
```

`datumctl alb describe ALB_NAME` also shows whether Basic Auth is on. To turn Basic Auth off, run the following command:

```bash
datumctl alb auth unset ALB_NAME
```

To confirm that it works, request the load balancer with and without credentials:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://HOSTNAME/            # 401
curl -s -o /dev/null -w '%{http_code}\n' -u admin https://HOSTNAME/   # prompts for the password, then 200
```

### Give each user their own password

`alb auth set` gives every user the same password. To give each user their own, replace the `.htpasswd` lines in the Secret it created:

```bash
entry() { printf '%s:{SHA}%s\n' "$1" "$(printf '%s' "$2" | openssl dgst -sha1 -binary | base64)"; }
htpasswd=$( { entry admin 'first-long-random-password'; entry editor 'second-long-random-password'; } | base64 | tr -d '\n')
datumctl patch secret ALB_NAME-basic-auth --type=merge \
  -p "{\"data\":{\".htpasswd\":\"$htpasswd\"}}"
```

Envoy picks up the change within seconds, and `alb auth list` and `alb describe` still show the users. Running `alb auth set` again replaces them with one shared password.

## Set up Basic Auth with a SecurityPolicy

A manifest takes two resources: a Secret holding an `htpasswd` list, and a `SecurityPolicy` that points at it and at the load balancer's route. The route has the same name as the load balancer. See [Where a SecurityPolicy attaches](/alb/authentication/overview#where-a-securitypolicy-attaches).

Use a manifest when you want Basic Auth together with other settings, such as CORS, in one policy, or on a single path. `datumctl alb auth list` and `datumctl alb describe` don't show Basic Auth set up this way, so don't also run `alb auth set` on the same load balancer.

### Step 1: Generate an htpasswd entry for each user

Envoy accepts **SHA entries only** (`{SHA}`). Other formats, such as bcrypt and APR1, aren't supported. SHA is a fast, unsalted hash, so use long random passwords.

<Tabs>
  <Tab title="macOS / Linux">

  ```bash
  entry() { printf '%s:{SHA}%s\n' "$1" "$(printf '%s' "$2" | openssl dgst -sha1 -binary | base64)"; }
  entry alice 'first-long-random-password'
  entry bob   'second-long-random-password'
  ```

  </Tab>
  <Tab title="Windows (PowerShell)">

  ```powershell
  function Entry($user, $password) {
    $sha1 = [System.Security.Cryptography.SHA1]::Create().ComputeHash([Text.Encoding]::UTF8.GetBytes($password))
    "${user}:{SHA}$([Convert]::ToBase64String($sha1))"
  }
  Entry alice 'first-long-random-password'
  Entry bob   'second-long-random-password'
  ```

  </Tab>
</Tabs>

Each line looks like `alice:{SHA}fAYATt6GBC1fG3rV/+TsArfpfqs=`.

### Step 2: Create the Secret and the policy

The Secret must use the key `.htpasswd`, have one line per user, and carry the `gateway-sync` label. Save this as `basic-auth.yaml`, with your own entries:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: ALB_NAME-htpasswd
  labels:
    networking.datumapis.com/gateway-sync: "true"
type: Opaque
stringData:
  .htpasswd: |
    alice:{SHA}fAYATt6GBC1fG3rV/+TsArfpfqs=
    bob:{SHA}7zQr7w5Y9jpYtGS5eu5Mwj1Qxz4=
---
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: SecurityPolicy
metadata:
  name: ALB_NAME-basic-auth
spec:
  targetRefs:
    - group: gateway.networking.k8s.io
      kind: HTTPRoute
      name: ALB_NAME
  basicAuth:
    users:
      name: ALB_NAME-htpasswd
    forwardUsernameHeader: X-Username
```

Apply it:

```bash
datumctl apply -f basic-auth.yaml
```

`forwardUsernameHeader` is optional. With it, your origin receives the signed-in user's name, such as `X-Username: bob`. Envoy sets the header itself, so a client can't fake it.

<Warning>
  Envoy also forwards the client's `Authorization` header to your origin, and that header carries the password, only base64-encoded. Trust your origin with it, or have the origin ignore it.
</Warning>

### Step 3: Check it

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://HOSTNAME/                                         # 401
curl -s -o /dev/null -w '%{http_code}\n' -u alice:first-long-random-password https://HOSTNAME/    # 200
```

A new or changed policy takes up to a minute to reach every location.

## Change or remove users

To add, remove, or change a user, edit the `.htpasswd` lines and apply the Secret again. Envoy picks up the change within seconds, with no change to the policy.

To remove Basic Auth set up with a manifest, delete the policy and the Secret while the load balancer still exists:

```bash
datumctl delete securitypolicy ALB_NAME-basic-auth
datumctl delete secret ALB_NAME-htpasswd
```

To remove Basic Auth set up with `datumctl alb auth set`, run `datumctl alb auth unset ALB_NAME`.

<Note>
  **Known issue:** `datumctl alb auth unset` and `datumctl alb delete` leave the Secret `ALB_NAME-basic-auth` behind, and deleting it can leave it in `Terminating` indefinitely, held by the finalizer `gateway.networking.datumapis.com/gateway-resource-replicator`. The Secret no longer protects anything. Don't remove the finalizer yourself. Contact support if you need it gone.
</Note>

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `500` on every request | The Secret is missing the `gateway-sync` label, or the policy names the wrong Secret. | Add the label, or fix `users.name` in the policy. |
| `401` with the right password | The entry isn't `{SHA}`, or the hash was made from a password with a trailing newline. | Regenerate the entry with `printf '%s'`, not `echo`. |
| No sign-in prompt | The policy isn't attached, or another policy already targets the route. | Check `targetRefs`, and run `datumctl describe securitypolicy` to look for `Conflicted`. |
| No password needed after you add CORS, JWT, or another policy | A route-level policy replaced the Gateway-level Basic Auth from `alb auth set`. | Put `basicAuth` in the route's policy, and run `alb auth unset`. |
| `alb auth list` doesn't show your users | Basic Auth was set up with a manifest. | Read the Secret, or use `alb auth set`. |

Useful commands:

```bash
datumctl get securitypolicies
datumctl get secrets
datumctl get httproutes
```

## When to use something else

Basic Auth is a shared-secret check. There's no sign-out, no expiry, and every request carries the password. For production:

- Use [OIDC](/alb/authentication/oidc) for people, so they sign in with your identity provider and leaving the company removes their access.
- Use [API keys](/alb/authentication/api-keys) or [JWT](/alb/authentication/jwt) for machines, so each client has its own credential that you can revoke without changing the others.
