gVPC is Datum's private networking for your workloads. You create a *network* in your project, attach [Compute](/compute/overview) workloads to it, and each Instance receives a private IPv6 address on that network. One network spans every location that your workloads run in, so you don't create a separate network for each region.

For the story behind gVPC, see [Meet me in the Galactic VPC](https://www.datum.net/blog/galactic-vpc-backbone/) on the Datum blog.

gVPC runs on Datum's global IPv6 backbone. Datum plans the addresses, carries the traffic, and keeps each network separate from every other network.

## How it works

A network belongs to a project, not to a location. You attach Compute workloads to a network, and every Instance of those workloads gets a private IPv6 address on it, in whichever location the Instance runs. Networks are isolated from each other, and public traffic reaches Instances only through Datum's [Application Load Balancer](/alb/overview). For details, see [Networks overview](/galactic-vpc/networks/overview).

## Features

gVPC provides the following features:

- **One network across locations:** A network is a single project-wide resource. Every workload that names it, in any location, attaches to the same network, and each Instance gets a private IPv6 address on it.
- **Automatic addressing:** Datum assigns address space to each network and an address to each Instance. You don't plan subnets.
- **Stable addresses when you need them:** Instances keep their addresses when Datum replaces them, and a workload can keep addresses reserved when it scales down.
- **Network services:** A [network service](/galactic-vpc/networks/network-services) gives a workload's Instances a stable name and named ports, so a load balancer can send traffic to them.
- **Declarative:** Networks are Kubernetes-style resources that you manage with the [`datumctl network` plugin](/galactic-vpc/operations), manifests, or GitOps tooling.

To learn what Datum is working on next, see [Planned capabilities](/galactic-vpc/limitations-and-roadmap#planned-capabilities).
