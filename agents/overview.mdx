Datum is built for agents as first-class users. Rather than wrapping an API in a chat interface, Datum exposes the same primitives people use, such as YAML manifests, `datumctl` commands, and [Kubernetes-style resources](/platform/kubernetes), in ways that agents can reason about reliably. This section covers the surfaces agents use to work with Datum.

## Agent surfaces

<CardGroup cols={2}>
  <Card title="Skills" icon="book-open" href="/agents/skills/index">
    Self-contained instructions agents load on demand. Install once, and agents know the canonical way to work with each Datum resource.
  </Card>
  <Card title="Datum MCP" icon="plug" href="/agents/datum-mcp">
    Model Context Protocol servers: one for live, authenticated access to your resources, and a hosted one for searching the docs.
  </Card>
  <Card title="llms.txt" icon="file-lines" href="/agents/llms-txt">
    An index of every docs page, plus the full text and a Markdown version of each page, for agents to fetch.
  </Card>
  <Card title="datumctl" icon="terminal" href="/datumctl/overview">
    The CLI. Agents run it directly for any platform action, with machine-readable output.
  </Card>
  <Card title="Patch" icon="robot" href="/datumctl/ai/assistant">
    Datum's own assistant. Ask it in plain language, or hand it a diagnostic question, with `datumctl assistant`.
  </Card>
</CardGroup>

## Which one should I use?

| If your agent needs to… | Use |
|---|---|
| Know *how* to do a Datum task, such as attaching a domain to a load balancer | [Skills](/agents/skills/index) |
| Read or change live Datum resources during a task | [Datum MCP](/agents/datum-mcp) |
| Find the right documentation | [Datum Docs MCP](/agents/datum-mcp#datum-docs-mcp) or [llms.txt](/agents/llms-txt) |
| Run commands directly, such as in a script or CI | [`datumctl`](/datumctl/overview) |
| Diagnose an open-ended problem, such as why a workload isn't available | [Patch](/datumctl/ai/assistant) |

These surfaces layer together. A typical agent session loads one or two relevant Skills, calls Datum MCP or `datumctl` to act, and fetches pages through `llms.txt` when it needs deeper context. For an open-ended diagnostic question, or a risky change across several resources, it can hand the task to Patch, which uses the same diagnostic tools with Datum's own guidance. To get started, see [Skills](/agents/skills/index).
