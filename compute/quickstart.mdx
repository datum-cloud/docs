In this quickstart, you deploy [Grafana](https://grafana.com/oss/grafana/), the open source dashboard and visualization app, to the Dallas location. You reach it through Datum's Application Load Balancer (ALB), log in from your browser, and then delete it.

The quickstart uses the `general-purpose` runtime class, which runs standard container images without changes, and the official `docker.io/grafana/grafana` image. Grafana fits in one Instance (1 vCPU and 2 GiB of memory), listens on IPv6, and starts without outbound internet access, so it runs on Compute without changes.

<Note>
  Compute is in preview, and the `v1alpha` API can change. Your project needs approved access to Compute before you can deploy, and Datum reviews access requests manually.
</Note>

## Before you begin

- Create a Datum Cloud account, an organization, and a project. For more information, see [Account setup](/platform/setup).
- Install `datumctl` and run `datumctl login`. For more information, see the [datumctl quickstart](/datumctl/quickstart).
- Make sure that you have permission to create compute and networking resources in the project, for example, through the **Compute Admin** and **Network Admin** roles.
- Install a text editor, a web browser, and `curl`.

## Set up your project

Complete these steps once for each project that runs Compute workloads. Other Compute guides assume that you've completed them.

<Steps>
  <Step title="Select your project">
    Compute commands run against a project. To make your project the active context, run the following command:

    ```bash
    datumctl ctx use ORG_ID/PROJECT_ID
    ```

    Replace the following:

    - `ORG_ID`: the ID of your organization.
    - `PROJECT_ID`: the ID of your project.

    To pick a project from a list instead, run `datumctl ctx use` with no arguments.
  </Step>

  <Step title="Install the compute plugin">
    The `compute` commands come from a plugin in the official Datum catalog. To install the plugin, run the following command:

    ```bash
    datumctl plugin install compute
    ```

    For more information about plugins, see [Using plugins](/datumctl/plugins/using-plugins).
  </Step>

  <Step title="Request access to Compute">
    To request access for your project and wait for a decision, run the following command:

    ```bash
    datumctl compute access request --wait
    ```

    Datum approves requests manually, so the wait can outlast the command's default 30-minute timeout. If the command times out, run `datumctl compute access` to check the state of your request. Continue when the status is `Active`.
  </Step>
</Steps>

## Deploy and use Grafana

<Steps>
  <Step title="Deploy Grafana">
    To deploy Grafana to Dallas (`us-central-1`) and publish it on a public URL, run the following command:

    ```bash
    datumctl compute deploy grafana \
      --image=docker.io/grafana/grafana:13.2.2 \
      --runtime-class=general-purpose \
      --location=us-central-1 \
      --http-port=3000
    ```

    The flags do the following:

    - `--image`: the container image to run, pinned to a Grafana release. Compute requires the registry host in the image reference, such as `docker.io`.
    - `--runtime-class=general-purpose`: runs the image as a standard container in a lightweight virtual machine. Without this flag, Datum uses the `unikernel` class, which needs a specially packaged image.
    - `--location=us-central-1`: runs one Instance in Dallas.
    - `--http-port=3000`: attaches Datum's [ALB](/alb/overview) to the workload and publishes port `3000`, where Grafana serves HTTP. Grafana listens on all IPv4 and IPv6 addresses, which matters because Instances have private IPv6 addresses only.

    The command asks you two questions:

    1. The first time you deploy in a project, the command asks whether to create a network named `default`. Enter `y`.
    2. The command prints a plan and asks `Apply? (Y/n)`. Enter `y`.

    The command then creates the workload, waits for the Instance to start, and publishes the URL. The first deploy can take a few minutes. The output is similar to the following:

    ```text
    Resolving workload "grafana" in project PROJECT_ID...
      Network "default" does not exist in project PROJECT_ID.
      Create it now? (Y/n): y
      network/default created
      Placement "default": locations=[us-central-1], min=1
      Runtime class:       general-purpose
      Network:             default
      HTTP service:        port 3000 → Datum-managed URL
                           Datum terminates TLS; serve plain HTTP on this port.
    Apply? (Y/n): y
      workload/grafana created
    Saved workload.yaml
    Waiting for rollout. Ctrl-C to detach (rollout continues in background).

      PLACEMENT  LOCATION      UPDATED  READY  OLD  PHASE
      default    us-central-1  0        0      0    Pending
      default    us-central-1  1        0      0    Updating
      default    us-central-1  1        1      0    Done
    Rollout complete in DURATION.

    Publishing...
      Backends     1 healthy across us-central-1
      Edge         programmed
      Certificate  issued

      https://stark-raven-b7k2m.datumproxy.net
    ```

    The rollout table adds a row each time the location's progress changes, so your rows can differ. `DURATION` is how long the rollout took.

    The last line is the hostname of the ALB that `--http-port` attached to the workload. Your hostname is different. The command also saves the workload definition to `workload.yaml` in the current directory.

    Grafana starts with a default administrator account whose user name and password are both `admin`. Anyone who finds the URL can try them, so set your own password in the next step before you share the URL.
  </Step>

  <Step title="Set the administrator password">
    The `datumctl compute deploy` flags don't set environment variables, so you set Grafana's `GF_SECURITY_ADMIN_PASSWORD` variable in a workload manifest. A password set this way also comes back if Datum replaces the Instance. To set the password, follow these steps:

    1. Copy the saved workload definition to a new file, so that a later flag-based deploy doesn't overwrite your changes:

       ```bash
       cp workload.yaml grafana.yaml
       ```

    2. Open `grafana.yaml` in a text editor, and add an `env` list to the `app` container, as in the following example:

       ```yaml
               sandbox:
                 containers:
                 - image: docker.io/grafana/grafana:13.2.2
                   name: app
                   env:
                   - name: GF_SECURITY_ADMIN_PASSWORD
                     value: ADMIN_PASSWORD
                   ports:
                   - name: http
                     port: 3000
                     protocol: TCP
       ```

       Replace `ADMIN_PASSWORD` with a strong password. Keep the rest of the file as it is.

    3. To update the workload from the manifest, run the following command:

       ```bash
       datumctl compute deploy -f grafana.yaml
       ```

    4. When the command asks `Apply? (Y/n)`, enter `y`. The command replaces the Instance with one that has the new password, and waits for the rollout. The output is similar to the following:

       ```text
       No changes detected.
       Apply? (Y/n): y
         workload/grafana updated
       Waiting for rollout. Ctrl-C to detach (rollout continues in background).

         PLACEMENT  LOCATION      UPDATED  READY  OLD  PHASE
         default    us-central-1  0        1      1    Pending
         default    us-central-1  1        0      0    Updating
         default    us-central-1  1        1      0    Done
       Rollout complete in DURATION.
       ```

       Your rollout rows can differ. The `No changes detected.` line appears because the summary compares only the image and the placements. The command still applies the new variable. The workload keeps its ALB and its hostname.

    The password is stored in plain text in `grafana.yaml` and in the workload. For a long-lived deployment, store it in a Secret instead. For more information, see [Configure a workload](/compute/configuration).

    From now on, update the workload with `datumctl compute deploy -f grafana.yaml`. A flag-based deploy replaces the whole template, removes the password variable, and puts the default `admin` password back the next time Datum replaces the Instance.
  </Step>

  <Step title="Check that Grafana is available">
    To list the workloads in your project, run the following command:

    ```bash
    datumctl compute workloads
    ```

    The output is similar to the following:

    ```text
    NAME      LOCATIONS      HEALTH      READY   UP-TO-DATE   PLACEMENTS   IMAGE                    AGE   URL
    grafana   us-central-1   Available   1/1     1/1          default      grafana/grafana:13.2.2   4m    https://stark-raven-b7k2m.datumproxy.net

    1 workloads — 1 Available, 0 Degraded, 0 Unavailable, 0 Unknown
    ```

    Continue when `HEALTH` is `Available` and `READY` is `1/1`. The `URL` column shows the ALB hostname from the deploy output.
  </Step>

  <Step title="Open Grafana in your browser">
    In your web browser, go to the URL from the last line of the deploy output, such as `https://stark-raven-b7k2m.datumproxy.net`. Datum's ALB serves Grafana over HTTPS, and Grafana shows its login page.

    If the browser can't find the site, wait a minute and try again. A new hostname can take a few minutes to resolve.

    To check Grafana from the command line as well, run the following command:

    ```bash
    curl WORKLOAD_URL/api/health
    ```

    Replace `WORKLOAD_URL` with the URL from the last line of the deploy output.

    The output is similar to the following:

    ```text
    {
      "database": "ok",
      "version": "13.2.2",
      "commit": "COMMIT"
    }
    ```

    `COMMIT` is the Git commit that the Grafana release was built from.
  </Step>

  <Step title="Log in to Grafana">
    To log in, follow these steps:

    1. On the Grafana login page, enter `admin` as the user name.
    2. Enter the password that you set in `grafana.yaml`.
    3. Click **Log in**. Grafana opens its home page.

    Grafana doesn't ask you to change the password, because you replaced the default password. You can now explore Grafana, for example, by adding a data source and building a dashboard.

    <Warning>
      Instances have no persistent disks. Grafana keeps dashboards, data sources, users, and settings on the Instance's local disk, so you lose them when the Instance restarts or Datum replaces it, including when you update the workload. Don't keep work in this Grafana that you want to keep.
    </Warning>
  </Step>

  <Step title="Optional: See the Instance">
    To list the workload's Instances, run the following command:

    ```bash
    datumctl compute instances --workload=grafana
    ```

    The output is similar to the following:

    ```text
    NAME                             WORKLOAD   LOCATION       INTERNAL IP                TYPE      AGE   STATUS
    grafana-default-us-central-1-0   grafana    us-central-1   fd20:4a3b:91c2::1:0:0/96   sandbox   3m    Available

    1 instances — 1 Available, 0 Pending, 0 Failed
    ```

    The `INTERNAL IP` column shows the Instance's private IPv6 address on the `default` network. The Instance has no public address, so traffic from the internet reaches Grafana only through the ALB.
  </Step>
</Steps>

## Clean up

To avoid using your project's compute quota, delete the resources that you created by following these steps:

1. To delete the workload, its Instance, and its ALB, run the following command:

   ```bash
   datumctl compute destroy grafana
   ```

2. Review the summary that the command prints.
3. Enter `y` to confirm. The command prints `workload/grafana deleted.`
4. Delete `grafana.yaml`, which contains your password in plain text, and `workload.yaml`.
5. Optional: If you don't plan to deploy more workloads, delete the `default` network:

   ```bash
   datumctl delete network default
   ```
