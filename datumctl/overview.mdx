<Note>
**Working with this CLI via an AI agent?** Agents can run `datumctl` directly. Use `-o json` and the structured errors described in [Output and scripting](/datumctl/output-and-scripting), and install Datum's [Skills](/agents/skills/index) so the agent knows the canonical commands for each resource. For an MCP client instead of a shell, see [Datum MCP](/agents/datum-mcp).
</Note>

`datumctl` is the command-line tool for working with Datum Cloud. It exposes a consistent resource model — the same `get`, `apply`, `describe`, and `delete` verbs across every resource type — so both developers and AI agents get a fast, predictable way to interact with Datum.

<Info>
  Ready to play? [Install](/datumctl/install) `datumctl` and get started.
</Info>

## Product plugins

Each Datum product adds its own commands to `datumctl` as an official [plugin](/datumctl/plugins/using-plugins). Install the ones you use, and run `datumctl plugin search` to see them all:

| Plugin | What it does | Documentation |
| --- | --- | --- |
| `alb` | Create and manage Application Load Balancers, their routes, hostnames, firewall, and basic authentication, and read their access logs. | [ALB operations](/alb/operations/overview) |
| `assistant` | Chat with Patch, the Datum Cloud assistant. | [AI assistant](/datumctl/ai/assistant) |
| `compute` | Build, deploy, scale, and debug Compute workloads. | [Compute commands](/datumctl/compute/overview) |
| `dns` | Manage DNS zones and records, check delegation, and import and export zone files. | [DNS operations](/domain-dns/operations) |
| `network` | Create and manage gVPC networks and network services. | [gVPC](/galactic-vpc/overview) |
| `search` | Search your resources by name and kind. | [Search across your resources](/datumctl/discovering-resources#search-across-your-resources) |
| `telemetry` | Query the logs in your project, including load balancer access logs. | [Query access logs](/alb/observability#query-access-logs-across-load-balancers) |

`datumctl --help` lists the plugins you have installed, and the plugins in the catalog that you haven't installed yet.

## How it works

At a high level, `datumctl` does three things:

1. **Authenticates you** - Opens a browser login, stores credentials securely, and refreshes tokens automatically.
2. **Talks to the Datum API** - Sends requests to create, read, update, and delete resources with authentication handled behind the scenes.
3. **Formats output** - Displays results as tables by default (supports JSON and YAML).
